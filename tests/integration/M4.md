# Actual M4 synthetic qualification

Run from a clean committed checkout on Linux x86_64 with SSE4.1, SSE4.2 and AVX,
Docker, and pinned Nextflow 26.04.6. The driver requires at least two Docker CPUs,
12 GiB engine memory, and 30 GiB free before image preparation. The required CI
job uses the standard public Ubuntu runner; it does not allocate a paid runner.

```bash
python scripts/run_m4_synthetic.py \
  --output-root /tmp/fresh-m4-integration \
  --expected-sha "$(git rev-parse HEAD)" --mode docker
```

`--mode preflight` observes the clean source, executable availability and storage
without creating a checkout, installing dependencies, pulling images or executing
callers. It never reports an execution pass. Local ARM and absent AVX conditions
fail before caller launch.

Actual mode installs the exact clean clone into an isolated environment and
verifies its package inventory before generating the separately registered M4
fixture. It freezes the independent three-site allele oracle and source/tool
hashes before launching any caller. It executes `gatk`, `deepvariant`, `both`, and
then resumes `both`, with one work directory and the same scientific parameters.
Expected trace counts are 26 completed; 23 cached plus three completed; 27 cached
plus one completed; and 28 cached. Selection manifests alone are specific to a
mode; all common preprocessing, isolated inputs, callers and collector identities
must be reused.

The driver independently inspects the real accepted BQSR BAM, index, complete read
inventory, OQ, exact 150M alignments and frozen allele-fragment counts. Native VCFs
must contain both expected SNVs with the intended genotypes and no nonreference
call at the reference control. Native VCF and DeepVariant gVCF indexes must support
full-contig random access matching sequential record identities. The index reader
is bcftools 1.15 from the same immutable DeepVariant image, whose pinned upstream
Dockerfile declares that utility version.

Each caller wrapper must mount only its copied task directory and use
`--network none`. The narrow DeepVariant inspector contains no allele oracle. It
hashes the five WES model files before inference, checks the pinned model metadata,
then reads every TFExample and CallVariantsOutput using image-provided TensorFlow
and protobufs. Qualification requires positive example and prediction counts,
finite normalized three-class probabilities, valid coordinates and unchanged
model hashes. The model-only inventory is insufficient for acceptance.

The driver saves separate reports for all four phases and a machine-readable
`evidence/integration-proof.json`. Only sanitized diagnostics, frozen acceptance
metadata and JSON contracts enter `evidence/`; BAM, FASTQ, reference, native VCF,
TFRecord and model bytes remain outside the upload directory. Privacy validation
quarantines unsafe candidates and leaves an explicitly failed M4 proof. The
required `m4-docker` CI job uploads this small evidence directory on success or
failure. Native scientific outputs and result contracts remain separately bound
by exact byte hashes.

A pass qualifies actual integration on invented data. It does not establish HG001
accuracy, capture-domain validity, normalization, benchmarking or deployment.
