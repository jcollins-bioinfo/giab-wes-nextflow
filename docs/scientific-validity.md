# Scientific validity boundaries

Canonical data, reference, domains and interpretation are stated in README. The shared preprocessing contract is BWA-MEM2 → coordinate sort → mark duplicates without removal → BaseRecalibrator → ApplyBQSR retaining OQ. M3 qualified this processing on invented inputs; canonical HG001 execution remains gated. Both callers receive identical accepted BAM/BAI, reference and calling-region byte identities. GATK consumes recalibrated QUAL; DeepVariant consumes OQ, so identical BAM bytes do not imply identical effective quality inputs.

[ADR 0012](adr/0012-m4-caller-execution-and-qualification.md) fixes GATK 4.7.0.0 HaplotypeCaller in single-sample direct VCF mode, with two native PairHMM threads and an explicit calling-confidence threshold of 30. The bounded 20 kb M4 qualification uses one unscattered task. It does not run GenotypeGVCFs or produce a GATK gVCF. DeepVariant 1.10.0 uses `run_deepvariant`, `model_type=WES`, and `use_original_quality_scores=true`; it retains its native VCF and auxiliary gVCF. Both branches preserve native annotations and filters. No additional exome hard-filter policy is applied in M4.

M5 will create benchmark derivatives through one shared, versioned normalization interface. Any symmetric downstream filtering policy, including missing-annotation behavior, must be preregistered before inspecting truth metrics. The M4 synthetic positive-SNV qualification does not establish indel accuracy, empirical BQSR adequacy, canonical domain validity or HG001 accuracy. Actual execution status is recorded in the milestone checkpoint and claim ledger.

DeepVariant 1.10 WES training included 57 HG001 replicates. Full chr1–22 is descriptive/in-sample; chr20–22 was excluded from documented training but remains same-individual locus-held-out sensitivity. No scalar winner, superiority, generalization, or clinical claim. Denominators cannot be conditioned on depth/callability/query/genotype.
